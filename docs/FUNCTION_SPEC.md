## 1. [MUST] 텍스트 입력 및 분석 요청
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 시작전

사용자가 중고거래/부동산 거래 관련 텍스트를 붙여넣고 분석을 요청한다. 

MVP는 텍스트 입력 중심으로 제한하며 파일 업로드/링크 크롤링은 제외한다.

1인 MVP 포인트

- 입력→분석→리포트로 이어지는 핵심 플로우를 가장 먼저 완성한다.

&nbsp;

**수용 기준:**
```
1. ○ 사용자가 텍스트를 입력하고 ‘분석하기’를 누르면 분석 요청이 생성된다.
2. ○ 최소 입력 길이 미만이면 분석 요청이 불가하고 안내 메시지가 표시된다.
3. ○ 요청 처리 중 로딩 상태가 표시된다.
4. ○ 실패 시 재시도 동작이 제공된다.
```


### 1.1 [MUST][W2] 텍스트 입력 화면(분석 대상 붙여넣기)
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 시작전

사용자가 중고거래 글/채팅/부동산 매물·계약 안내 텍스트를 붙여넣거나 직접 입력할 수 있는 화면을 제공한다. 개인정보 입력 주의 문구를 함께 노출한다.

근거: 분석 경험의 시작점이며 React에서 빠르게 만들 수 있어 1인 MVP에 필수다.


#### 1.1.1 [W2] 입력 예시/가이드 문구 노출

입력 영역 근처에 예시(가능한 텍스트 유형)와 ‘어떤 정보를 붙여넣으면 좋은지’ 가이드 문구를 노출한다.
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 시작전


#### 1.1.2 [W2] 민감 정보 입력 경고(자동 감지)

전화번호/계좌번호/주민번호 형태로 보이는 문자열이 입력되면 경고를 띄우고, 사용자가 마스킹 후 진행하도록 안내한다.
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 시작전


#### 1.1.3 [W2] 텍스트 빠른 동작(붙여넣기/전체 지우기)

붙여넣기 편의(포커스/단축 버튼)와 ‘전체 지우기’ 버튼을 제공해 반복 사용성을 높인다.
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 시작전


### 1.2 [MUST][W2] 분석 요청 실행 및 로딩 상태
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 시작전

‘분석하기’ 버튼으로 분석 요청을 보내고, 처리 중에는 로딩 상태(진행 중 안내)를 표시한다. 중복 클릭을 방지한다.

근거: FastAPI 연동과 사용자 피드백(로딩)은 MVP 품질을 결정하는 최소 요건이다.


#### 1.2.1 [W2] 요청 생성 API 호출 및 상태 관리

‘분석하기’ 클릭 시 요청 생성 API를 호출하고, 성공/실패/진행 중 상태를 화면 상태로 관리한다.
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 시작전


#### 1.2.2 [W2] 중복 요청 방지(버튼 비활성/디바운스)

요청 진행 중에는 버튼을 비활성화하고, 빠른 연타 시에도 중복 요청이 생기지 않게 한다.
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 시작전


#### 1.2.3 [W2] 로딩 UI(예상 대기 안내)

로딩 스피너와 함께 ‘보통 몇 초 걸리는지’ 등 간단한 대기 안내 문구를 제공한다.
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 시작전


### 1.3 [MUST][W2] 입력 검증(최소 글자 수/안내 메시지)
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 시작전

최소 입력 길이 미만일 때 분석 요청을 막고, 왜 불가한지 안내 메시지를 보여준다.

근거: 낮은 비용으로 실패 케이스를 줄여 UX를 안정화할 수 있어 1인 개발에 필수다.


#### 1.3.1 [W2] 최소 글자 수 설정(50자)

분석 요청 가능한 최소 입력 길이를 50자로 설정하고, 미만일 때 요청을 차단한다.
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 시작전


#### 1.3.2 [W2] 입력 불가 안내 메시지 표시

최소 글자 수 미만일 때 '50자 이상 입력해주세요' 등 명확한 안내 메시지를 입력 필드 아래에 표시한다.
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 시작전


#### 1.3.3 [W2] 실시간 글자 수 카운트 표시

사용자가 현재 입력한 글자 수를 실시간으로 표시해(예: '45/50자') 남은 글자 수를 쉽게 파악할 수 있게 한다.
> **중요도**: 🟢 낮음 | **진행 상태**: ⚪ 시작전


### 1.4 [MUST][W6] 요청 실패 처리 및 재시도
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 시작전

분석 요청 실패 시 오류 안내와 ‘다시 시도’를 제공한다.

MVP 원칙
- 오류는 2~3가지 수준(네트워크/시간 초과/일시 오류)으로만 구분한다.
- 과도한 예외 처리/운영 정책은 문서에서 제외하고, 재시도 경험을 우선 완성한다.


#### 1.4.1 [W6] 오류 유형별 안내 문구

네트워크 오류/서버 오류/시간 초과 등 주요 실패 케이스별로 사용자에게 보여줄 안내 문구를 구분해 제공한다.

안내 문구(짧게 · MVP)
- 네트워크 오류: “인터넷 연결을 확인해주세요.”
- 시간 초과: “처리가 지연됐어요. 다시 시도해주세요.”
- 서버 오류: “일시적으로 문제가 있어요. 잠시 후 다시 시도해주세요.”

표시 규칙(MVP)
- 오류 안내는 로딩 영역(또는 결과 영역) 내 ‘같은 위치’에 노출해 사용자가 혼란스럽지 않게 한다.
- 각 문구 아래에 공통 보조 문구 1줄을 함께 노출할 수 있다: “문제가 계속되면 잠시 후 다시 시도해주세요.”
- 가능하면 ‘다시 시도’ 버튼을 함께 제공한다(버튼 동작은 ‘재시도 동작(즉시 재요청)’ 상세 기능을 따른다).
- 기술 용어(HTTP, 서버 코드 등)는 사용자에게 직접 노출하지 않는다.

문구 톤 규칙
- 단정/비난 금지: “사용자 오류” 등 표현 금지
- 안내 톤: 짧고 차분하게, 다음 행동(다시 시도/연결 확인)을 바로 알 수 있게 쓴다.
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 시작전


#### 1.4.2 [W6] 재시도 동작(즉시 재요청)

‘다시 시도’ 버튼을 제공하고, 마지막 입력 텍스트와 체크리스트 선택값을 유지한 채 동일 요청을 다시 보낼 수 있게 한다.

동작 규칙(MVP)
- ‘다시 시도’ 클릭 시 즉시 동일 요청을 재전송한다(추가 입력 요구 없음).
- 재요청 중에는 버튼을 비활성화하고 로딩 상태를 표시한다.
- 재시도 성공 시: 기존 오류 안내를 숨기고 결과 화면으로 이동(또는 결과를 갱신)한다.
- 재시도 실패 시: 오류 안내를 갱신하고, 사용자가 다른 조치를 할 수 있도록 ‘문제 해결 가이드(사용자 점검)’를 함께 노출한다.

버튼/문구(권장)
- 버튼: “다시 시도”
- 보조 안내(선택): “입력 내용은 유지돼요.”
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 시작전


#### 1.4.3 [W6] 문제 해결 가이드(사용자 점검)

재시도 전 사용자가 확인할 수 있는 간단 점검 가이드를 3~5개로 제공한다.

점검 항목(짧게 · MVP)
- 인터넷 연결을 확인한다.
- 입력 텍스트가 최소 글자 수를 넘는지 확인한다.
- 전화번호/계좌/이메일 등 민감 정보를 마스킹했는지 확인한다.
- 잠시 후 다시 시도한다(일시 오류 가능).
- 계속 실패하면 다른 텍스트로 다시 시도한다(붙여넣기 오류/형식 문제 가능).

표시 규칙(MVP)
- ‘시간 초과/서버 오류’ 등 일시적 오류에서는 우선 ‘잠시 후 다시 시도’ 항목을 상단에 노출한다.
- ‘네트워크 오류’에서는 ‘인터넷 연결 확인’ 항목을 상단에 노출한다.
- 가이드는 오류 안내 영역 바로 아래에 3~5개 bullet로 짧게 노출한다(스크롤 없이 보이는 높이 권장).
- ‘다시 시도’ 버튼이 함께 있을 때는 버튼 아래(또는 옆)에 가이드를 붙여, 다음 행동 흐름이 끊기지 않게 한다.

문구 톤 규칙(MVP)
- 사용자를 탓하는 표현 금지(“입력을 잘못했어요” 등).
- “지금 바로 해볼 수 있는 것” 톤으로 짧게 쓴다.
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 시작전

## 2. [SHOULD] 체크리스트 기반 위험 신호 보완(선택)
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 시작전

AI 분석을 보완하기 위해 사용자가 간단 체크리스트(8~12개)를 선택할 수 있다. 체크리스트는 선택 사항이며, MVP의 필수 흐름을 방해하지 않는다.

**수용 기준:**
```
1. ○ 체크리스트는 선택형(체크박스)으로 제공되며 8~12개 수준이다.
2. ○ 체크리스트를 선택하지 않아도 분석은 가능하다.
3. ○ 선택한 체크 신호가 결과에 반영되었음을 표시한다.
```


### 2.1 [SHOULD] 체크리스트 항목 UI(8~12개)
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 시작전

중고거래/부동산 공통 위험 신호 체크리스트를 체크박스로 제공한다. 선택은 선택 사항이며, 8~12개 수준으로 제한한다.

근거: LLM만으로 불안한 부분을 보완해 발표 설득력을 높이지만, 없이도 핵심 흐름은 성립한다.


#### 2.1.1 [W5] 공통 체크 항목 10개 문구 확정

MVP 체크리스트 공통 위험 신호 10개를 문구로 확정한다. 예: 선입금/보증금 먼저 요구, 직거래 회피(택배만/안전결제 거부), 시세 대비 과도한 저가, 신분/소유 증빙 거부, 연락 회피/통화 거부, 장소·시간을 계속 바꿈, 계약/거래 조건이 비정상적으로 단순(서류 회피), 급하게 결정을 압박, 외부 메신저/링크로 유도, 제3자 계좌/대리인 거래 요구.
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 시작전


### 2.2 [SHOULD] 체크 항목 설명(도움말/툴팁)
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 시작전

각 체크 항목에 1줄 이상의 설명을 제공해 사용자가 의미를 이해할 수 있게 한다.

근거: 추가 개발량이 크지 않으면서 체크리스트 사용성을 올려주는 ‘가성비’ 개선이다.


#### 2.2.1 [W5] 체크 항목 도움말 아이콘 및 텍스트

각 체크리스트 항목 옆에 물음표(?) 아이콘을 제공하고, 클릭 시 해당 항목의 설명(1줄 이상)을 툴팁 또는 모달로 표시한다.
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 시작전


#### 2.2.2 [W5] 체크 항목 설명 문구 확정(10개)

10개 체크 항목 각각에 대해 1줄 이상의 이해하기 쉬운 설명 문구를 작성한다. 예: '선입금 먼저 요구' → '선입금/보증금을 미리 요구하는 경우 환불 분쟁이 어려울 수 있습니다.'
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 시작전


### 2.3 [SHOULD] 체크리스트 제출값을 분석 결과에 반영 표시
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 시작전

사용자가 선택한 체크 항목이 위험 신호에 반영되었음을 결과 화면에서 표시한다(예: ‘체크리스트 신호 포함’ 배지/문구).

근거: ‘내 입력이 반영됐다’ 신뢰를 주지만, MVP 핵심 결과(리포트) 자체와는 분리 가능하다.


#### 2.3.1 [W5] 체크리스트 선택 항목 배지/문구 표시

결과 화면에서 사용자가 선택한 체크 항목을 배지 또는 문구('체크리스트 신호 포함')로 표시해 분석에 반영되었음을 명확히 한다.
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 시작전


#### 2.3.2 [W5] 체크 항목별 결과 섹션 구분

위험 신호 요약 섹션에서 'AI 탐지 신호'와 '체크리스트 신호'를 시각적으로 구분해 노출한다(색상/배지/문구).
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 시작전

## 3. [MUST] 위험도 리포트 생성(요약 + 점수)
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 시작전

텍스트 분석 결과와(선택) 체크리스트 신호를 바탕으로 위험도(점수/등급)와 핵심 위험 신호(3~5개)를 요약 리포트로 제공한다. 결과는 ‘판정’이 아니라 ‘추가 확인을 돕는 참고’로 안내한다.

포트폴리오 포인트
- LLM 활용(요약/근거) + 규칙 기반 점수화를 함께 보여준다.

**수용 기준:**
```
1. ○ 리포트에 위험도 점수/등급이 표시된다.
2. ○ 핵심 위험 신호가 3~5개로 요약되어 표시된다.
3. ○ 결과 화면에 참고용/면책 문구가 표시된다.
4. ○ 입력 텍스트 전문을 그대로 재노출하지 않는다(요약/부분 근거만).
```


### 3.1 [MUST][W3] 위험도 표시(점수/등급)
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 시작전

분석 완료 후 위험도를 점수(0~100)와 등급(LOW/MEDIUM/HIGH)으로 표시한다.

근거
- 규칙 기반 점수 결과를 한눈에 이해시키는 핵심 요소다.

표시 규칙(MVP)
- 등급 문구는 단정이 아닌 참고용 톤을 유지한다.
- 색상만으로 구분하지 않고 텍스트로도 구분한다.


#### 3.1.1 [W3] 위험도 표현 방식 확정(점수+등급)

위험도를 0~100 점수와 낮음/보통/높음 등급을 함께 표시하고, 색상 대신 텍스트로도 구분한다.
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 시작전


### 3.2 [MUST][W4] 핵심 위험 신호 요약(3~5개)
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 시작전

초기 MVP에서는 사용자가 체크리스트로 선택한 신호가 곧 ‘핵심 위험 신호’가 된다. 결과 화면에는 선택된 신호 중 점수가 높은 순으로 3~5개를 우선 노출하고, 나머지는 ‘선택한 신호 더 보기’로 펼쳐 볼 수 있게 한다.

표시 규칙(MVP)
- 기본 노출: 상위 3~5개
- 정렬: 신호 점수 높은 순(동점이면 고정 순서)
- 단정 표현 금지(‘사기 확정’ 등)

제외(초기 MVP)
- 텍스트 자동 추출/요약(LLM)

완료 기준
- 체크리스트 선택값만으로도 항상 같은 순서/내용으로 표시된다.


#### 3.2.1 [W4] 위험 신호 카드(근거 요약 포함)

각 위험 신호를 카드/리스트로 보여주고, 왜 위험한지 1줄 근거 요약을 함께 제공한다.

카드 구성(권장)
- 제목: 위험 신호명
- 보조 정보: 심각도 배지(높음/중간/낮음) + (선택)탐지 신뢰도(낮음/중간/높음)
- 근거 영역(필수): “탐지 근거(일부)” 1줄
- 설명 영역(필수): “왜 위험한가” 1문장
- 다음 행동(필수): CTA 1~2개
  1) 확인 문구 보기(템플릿 섹션으로 이동 또는 모달/드로어)
  2) 추천 문구 복사(해당 신호 우선 템플릿 1~3개 복사)

표시 규칙(MVP)
- 카드 수: 3~5개만 노출(요약 원칙)
- 정렬: 심각도 높은 순(동일하면 근거 명확도/신뢰도 순)
- 근거 형태 우선순위
  1) 1줄 요약(권장)
  2) 부분 인용(필요 시): 최대 80자(권장 50자) + 말줄임표
- 근거 문구에는 항상 ‘일부’ 표기 포함: “탐지 근거(일부)”, “관련 표현(일부)” 등
- ‘더 보기’는 같은 근거의 길이만 확장(최대 2배)하며, 전문 공개로 이어지지 않는다.
- “원문 보기/전체 보기/전문 보기” 류의 문구/버튼 금지

개인정보/안전 규칙(연동)
- 근거 영역에는 민감 정보 자동 마스킹을 항상 적용한다(전화번호/계좌/이메일/주민번호/카드/주소 등).
- URL/링크는 원칙적으로 근거에 노출하지 않고, 필요 시 도메인만 남기고 마스킹한다.
- 마스킹으로 문맥 이해가 어렵다면, 인용을 포기하고 ‘왜 위험한가’ 1문장 설명을 우선한다.

문구 톤 가이드
- 단정 금지: “사기 확정/안전함” 등 표현 금지
- 권장 톤: “추가 확인이 필요해요”, “가능하면 이렇게 확인해보세요” 등 안내 톤

모바일 배치(권장)
- 카드 1개당 6줄 내로 요약(제목 1줄, 배지 1줄, 근거 1줄, 설명 2줄, 버튼 1줄)
- 버튼은 1차 CTA(확인 문구 보기)를 우선, 2차 CTA(추천 문구 복사)는 아이콘/보조 버튼으로 처리 가능
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 시작전


#### 3.2.2 [W4] 위험 신호 우선순위/심각도 표시

요약된 3~5개 위험 신호 각각에 ‘높음/중간/낮음’ 등 심각도를 함께 표시해 사용자가 무엇부터 확인해야 하는지 알 수 있게 한다.

표시 규칙(MVP)
- 각 위험 신호 카드 제목 옆에 심각도 배지 1개를 표시한다: 높음 / 중간 / 낮음
- 색상만으로 구분하지 않고 텍스트(배지 문구)로도 구분한다.
- 정렬은 심각도 높은 순을 기본값으로 한다(동일 심각도면 탐지 신뢰도/근거 명확도 순).
- 심각도 배지는 각 카드에서 항상 같은 위치(제목 오른쪽)를 기본으로 고정한다.

심각도 판정 가이드(간단)
- 높음: 금전 요구(선입금/보증금), 외부 링크/앱 설치 유도, 제3자 계좌/명의 불일치, 신분/소유 증빙 거부 등 ‘즉시 중단/추가 확인’이 필요한 신호
- 중간: 직거래 회피, 연락 회피, 약속 변경 반복, 급한 압박 등 ‘추가 확인’이 필요한 신호
- 낮음: 단독으로는 결정적이지 않지만 다른 신호와 결합 시 의미가 커지는 약한 신호

문구 규칙
- 단정 금지: “사기 확정” 등 금지
- 안내 톤: “추가 확인이 필요해요” 유지

예외/불확실 처리(MVP)
- AI가 심각도를 산정하지 못하면 ‘중간’으로 기본 표기하고, 배지 옆(또는 카드 하단)에 “상황에 따라 달라질 수 있어요” 안내를 함께 노출한다.
- 동일 심각도 신호가 3개 이상이면 카드 하단에 “중요도 높은 항목부터 확인해보세요” 안내 1줄을 추가한다.
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 시작전


#### 3.2.3 [W4] 신호별 권장 확인 행동 연결(템플릿 연동)

각 위험 신호 카드에서 바로 ‘확인 질문/증빙 요청 템플릿’으로 이어지게 연결한다.

동작 규칙(MVP)
- 각 위험 신호 카드 하단에 CTA 2개를 제공한다.
  1) “확인 문구 보기” : 해당 신호에 매핑된 템플릿 목록을 기본적으로 모달/드로어(모바일: 바텀시트)로 연다. (예외: 동일 화면 내 템플릿 섹션이 항상 노출되는 구성이라면 섹션으로 스크롤 이동)
  2) “추천 문구 복사” : 해당 신호의 우선 템플릿 1~3개를 한 번에 클립보드로 복사
- 신호별 매핑 템플릿이 없으면(예외) 공통 템플릿 TOP 3를 대신 사용하고, “공통 문구를 보여드려요” 안내를 노출한다.

문구/안전 규칙
- 단정 금지: “사기 확정” 등 표현 금지, “추가 확인이 필요해요” 톤 유지
- 개인정보 주의: 복사 실행 후 토스트로 “민감 정보는 마스킹 후 사용하세요” 1줄을 항상 노출

버튼 문구(권장)
- 확인 문구 보기 / 추천 문구 복사

예외/실패 처리
- 클립보드 복사 실패 시: “복사가 어려워요. 아래 문구를 직접 복사해주세요” 안내와 함께 복사용 텍스트 박스를 노출한다.
- 템플릿 섹션 이동이 어려운 화면(모달 내부 등)에서는 ‘모달/드로어 열기’를 기본으로 사용한다.

추가 참고
- 연결된 복사/토스트/실패 처리의 상세 규칙은 ‘템플릿 복사 기능’의 상세 기능을 따른다.
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 시작전


#### 3.2.4 [W4] 신호별 근거 요약(1줄) 표준화

각 위험 신호에 대해 ‘탐지 근거’ 1줄 요약을 공통 포맷으로 제공한다.

표시 포맷(권장)
- 근거: “(부분 인용/요약 — 민감 정보는 마스킹)”
- 왜 위험한가: “(1문장 설명)”

작성 규칙
- 인용/요약은 1문장, 최대 80자 내(권장 50자 내)
- 민감 정보(전화번호/계좌번호/이메일/주민번호 형태)는 자동 마스킹
- 단정 표현 금지(‘사기 확정’ 등) → ‘의심 신호’, ‘추가 확인 필요’ 표현 사용
- 사용자를 다음 행동으로 연결: 문장 끝을 “확인 문구 보기”로 이어지게 톤을 맞춘다.

예시(형식)
- 근거: “안전결제 말고 선입금 먼저 해주세요”(010-****-1234)
- 왜 위험한가: 선입금을 요구하는 경우 환불·분쟁 대응이 어려울 수 있어 추가 확인이 필요해요.
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 시작전


### 3.3 [MUST][W4] 면책/주의 문구 노출
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 시작전

결과가 참고용이며 최종 판단은 사용자에게 있음을 명확히 안내한다(과신 방지).

근거: AI 결과의 과신 리스크를 최소 비용으로 낮추는 필수 안전장치다.


#### 3.3.1 [W4] 면책/가이드 고정 노출

결과 상단 또는 위험도 근처에 ‘참고용’ 안내를 고정 노출한다.

고정 문구(권장)
- “이 리포트는 참고용입니다. 사기 여부를 판정하지 않으며, 최종 판단과 책임은 사용자에게 있습니다.”

함께 노출할 짧은 안내(고정 2개)
- “민감 정보(전화번호/계좌번호/주민번호 등)는 입력·저장·공유 전에 반드시 마스킹하세요.”
- “위험도가 낮아도 안전을 보장하지 않습니다. 안전결제/대면 확인 등 기본 수칙을 지키세요.”

표시 규칙(MVP)
- 결과 화면에서 항상 보이게 고정(상단 스티키 또는 위험도 카드 내부)
- 모바일에서는 2줄 이내로 보이게 줄임 표기(‘자세히’ 토글로 전체 노출)
- ‘자세히’ 펼침에는 위 3문구 원문을 그대로 노출
- 과도한 경고로 보이지 않게 기본은 안내 톤으로 유지

금지 규칙
- “안전합니다/사기입니다” 같은 단정 표현 금지
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 시작전


### 3.4 [MUST][W4] 입력 텍스트 재노출 최소화(요약/근거)
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 시작전

결과 화면에서 입력 텍스트 전문을 그대로 보여주지 않는다. 초기 MVP에서는 LLM이 없으므로 요약/인용/근거 연결을 만들지 않고, ‘입력 텍스트는 참고 컨텍스트’로만 취급한다.

표시 원칙(MVP)
- 결과 화면에는 선택된 체크리스트 신호 목록만 노출한다.
- 입력 텍스트 전문 재노출(원문 보기/전체 보기/전문 보기) 금지.

제외(초기 MVP)
- LLM 기반 요약/인용/근거 생성

완료 기준
- 결과 화면 어디에서도 사용자가 입력한 텍스트 전문이 다시 보이지 않는다.


#### 3.4.1 [W4] 요약/인용 표시 규칙(최소화)

결과 화면에는 입력 텍스트 전문을 노출하지 않고, 핵심 문장 1~3개만 짧게 인용하거나 요약으로 대체한다. 사용자가 ‘원문 보기’를 기대하지 않도록 UI 문구를 정리한다.

표시 원칙(MVP)
- 원문 전체 노출 금지: 결과 화면 어디에서도 ‘전문’ 형태로 재노출하지 않는다.
- 인용은 최대 3개: 위험 신호 근거로 필요한 경우에만 1~3개 문장(또는 짧은 구절)만 노출한다.
- 길이 제한: 인용 1개당 80자 내(권장 50자 내)로 자른다(말줄임표 사용).
- 요약 우선: 근거가 충분하면 인용 대신 ‘요약’ 문장으로 대체한다.

UI 문구 규칙
- 금지 문구: “원문 보기”, “전체 보기”, “전문 보기” 등 전체 텍스트를 떠올리게 하는 표현 금지
- 권장 문구: “근거 요약”, “관련 표현(일부)”, “탐지 근거(일부)” 등 ‘일부’임을 명시

상호작용(토글) 규칙
- ‘더 보기’는 길이 확장(같은 인용/요약을 조금 더 길게) 용도로만 사용한다.
- ‘더 보기’를 눌러도 전문으로 확장되지 않으며, 최대 2배 길이까지만 확장한다.

개인정보 안전 규칙(연동)
- 인용/요약 영역에는 민감 정보 자동 마스킹 규칙을 항상 적용한다(전화번호/계좌/이메일/주민번호 형태 등).
- 마스킹 규칙의 상세는 ‘민감 정보 마스킹 규칙 적용’ 상세 기능을 따른다.
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 시작전


#### 3.4.2 [W4] 민감 정보 마스킹 규칙 적용

인용/요약 영역에 전화번호, 계좌번호, 이메일 등 민감 정보 형태가 포함되면 자동 마스킹 처리한다.

마스킹 대상(MVP)
- 전화번호(휴대폰/유선)
- 계좌번호(국내 주요 형식)
- 이메일
- 주민등록번호(형태 탐지 시 전부 마스킹)
- 카드번호(형태 탐지 시 전부 마스킹)
- 주소(‘시/구/동/로/번지’ 등 패턴 + 숫자 포함 시 부분 마스킹)

마스킹 방식(권장 포맷)
- 전화번호: 010-1234-5678 → 010-****-5678 (하이픈/공백 유무 모두 대응)
- 유선번호: 02-123-4567 → 02-***-4567
- 이메일: abcd@example.com → ab**@ex****.com (아이디 앞 2글자만 유지, 도메인 일부 마스킹)
- 주민등록번호: 900101-1234567 → ******-*******
- 카드번호: 1234-5678-9012-3456 → ****-****-****-****
- 계좌번호: 숫자열 길이 10~16자리(하이픈 포함 가능)로 탐지되면 앞 2~4자리와 뒤 2자리만 남기고 나머지 마스킹
  예) 110-123-456789 → 110-***-****89
- 주소: ‘서울특별시 강남구 테헤란로 123’ → ‘서울특별시 강남구 테헤란로 ***(상세 생략)’처럼 상세 번지/호수/동·층 정보를 우선 마스킹

표시/안전 규칙
- 마스킹은 결과 화면의 모든 인용/요약/근거 영역에 항상 적용한다.
- 사용자가 입력창에 민감 정보를 넣었더라도, 결과 화면에서 재노출되는 순간에는 반드시 마스킹된 형태로만 보여준다.
- 마스킹이 과도해 의미가 사라지면(예: 짧은 문자열) 해당 인용은 노출하지 않고 ‘근거 요약’으로 대체한다.
- 오탐(무관한 숫자 마스킹) 가능성이 있으므로, 숫자열 마스킹은 ‘계좌/카드/주민번호’ 패턴 우선 후 일반 숫자열로 확장한다(보수적으로 적용).

추가 예외 규칙(MVP)
- 사용자가 입력한 텍스트에 이미 ‘****’ 등 마스킹 문자가 포함돼 있으면, 그 구간은 원문 복원 없이 그대로 유지한다.
- URL/링크는 원칙적으로 인용/요약에 노출하지 않고, 필요한 경우 도메인만 남기고 나머지는 마스킹한다(예: https://example.com/a/b → example.com/…)
- 마스킹 처리로 인해 문맥 이해가 어렵다면, 인용 대신 ‘왜 위험한가’ 1문장 설명을 우선 노출한다.
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 시작전


#### 3.4.3 [W4] 인용 근거와 위험 신호 연결 표시

각 핵심 위험 신호에 대해 ‘어떤 표현/문장 때문에 탐지됐는지’를 사용자에게 연결해 보여준다. 단, 근거는 짧은 인용(부분 마스킹 포함) 또는 1줄 요약으로 제한해 입력 텍스트 재노출을 최소화한다.

표시 목표(MVP)
- 사용자가 “왜 이런 위험 신호가 나왔는지”를 3초 안에 이해한다.
- 입력 텍스트 ‘전문’ 재노출 없이도 근거를 납득할 수 있다.

표시 규칙
- 신호 1개당 근거 1개를 기본으로 한다(예외적으로 최대 2개).
- 근거 형태는 우선순위를 둔다.
  1) 1줄 요약(권장): 원문 인용 대신 의미만 요약
  2) 부분 인용(필요 시): 최대 80자 내(권장 50자), 말줄임표 사용
- 근거에는 항상 ‘일부’임을 표시한다: “탐지 근거(일부)”, “관련 표현(일부)” 등.
- 근거 영역에는 민감 정보 자동 마스킹을 항상 적용한다(전화번호/계좌/이메일/주민번호/카드/주소 등).
- 마스킹이 과도해 의미가 사라지면 인용을 포기하고 1줄 요약으로 대체한다.

상호작용 규칙
- ‘더 보기’는 근거의 길이만 조금 확장(최대 2배)하며, 전문 공개로 이어지지 않는다.
- “원문 보기/전체 보기/전문 보기” 류의 CTA는 금지한다.

연결 방식(권장 UI)
- 위험 신호 카드 내부에 근거 영역을 함께 표시한다.
- 근거 라벨 예: “탐지 근거(일부)”
- 근거 아래에 ‘왜 위험한가’ 1문장 설명을 둔다(가능하면).

예시(형식)
- 탐지 근거(일부): “안전결제 말고 선입금 먼저…”
- 왜 위험한가: 선입금을 요구하는 경우 환불·분쟁 대응이 어려울 수 있어 추가 확인이 필요해요.

금지 규칙
- 단정 표현 금지: “사기 확정/안전함” 등
- 전문 재노출을 유도하는 문구/버튼 금지

추가 연결(템플릿 연동)
- 가능하면 각 위험 신호 카드에서 [추가 확인 질문/요청 템플릿] 섹션으로 바로 이어지게 CTA(예: “확인 문구 보기”)를 제공한다.
- 템플릿이 없는 신호의 경우 공통 템플릿 TOP 3로 대체하고, “공통 문구를 보여드려요” 안내를 노출한다.
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 시작전

### 3.6 [MUST][W3] 위험도 산출 로직(규칙 기반)

체크리스트로 선택된 위험 신호를 입력으로 받아, 신호별 고정 점수를 합산해 riskScore(0~100)와 riskLevel(LOW/MEDIUM/HIGH)을 산출한다. MVP는 과설계 없이 규칙 기반으로 단순화한다.

포함 범위(MVP)

## 4. [NICE TO HAVE] 추가 확인 가이드(템플릿)

**수용 기준:**
```
1. ○ 결과 화면에 ‘추가 확인’ 섹션이 존재한다.
2. ○ 상황별로 3~8개의 템플릿을 추천한다.
3. ○ 템플릿은 복사 가능하다(간단 버튼).
```


### 4.1 [NICE TO HAVE] 추가 확인 질문/요청 템플릿 추천
> **중요도**: 🟢 낮음 | **진행 상태**: ⚪ 시작전

위험 신호에 따라 거래 상대에게 확인할 질문/요청할 증빙 템플릿을 추천한다(상황별 3~8개).

근거: UX 임팩트는 크지만 템플릿 품질·안전성·매핑 규칙까지 잡아야 해 일정 리스크가 커서 후순위다.


#### 4.1.1 공통 템플릿 세트(10개) 제공

중고거래/부동산 공통으로 쓸 수 있는 확인 질문/증빙 요청 템플릿 10개를 기본 제공한다.

템플릿(공통 10개 · MVP)
1) “선입금(보증금) 없이 거래 가능할까요? 안전결제(에스크로) 또는 대면 거래로 진행하고 싶어요.”
2) “입금이 필요하다면, 예금주명(실명) 확인을 위해 계좌 명의와 본인 확인 가능한 자료를 받을 수 있을까요?”
3) “환불 조건/거래 조건(금액·일정·인도 방식)을 메시지로 정리해서 남겨주세요.”
4) “직거래가 어렵다면 안전결제(에스크로)로 진행할 수 있을까요?”
5) “제품/매물 상태 확인을 위해 사진 추가 또는 영상통화가 가능할까요?”
6) “택배 거래라면 발송 전 운송장과 포장/발송 과정을 간단히 촬영해 공유해주실 수 있을까요?”
7) “거래 장소/시간을 확정해서 메시지로 남겨주세요. 변경이 잦으면 거래를 중단하겠습니다.”
8) “가격이 시세보다 낮은 이유(하자/권리관계/소유 경위 포함)를 설명해주실 수 있을까요?”
9) “외부 링크/앱 설치는 어렵습니다. 필요한 정보는 여기서 텍스트로 보내주세요.”
10) “부동산/고가 거래라면 공인중개사 통해 진행하고, 등기/권리관계 확인 후 계약하겠습니다.”

운영/문구 규칙
- 단정 금지: “사기 확정/안전함” 등 표현 금지, ‘추가 확인’ 톤 유지
- 개인정보 주의: 템플릿 노출 영역 하단에 “민감 정보는 마스킹 후 사용하세요” 안내를 함께 노출(또는 복사 토스트로 대체)
- 위험 행동 유도 금지: 신분증 원본 요구, 원격 제어 앱 설치 유도 등 금지
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 시작전


#### 4.1.2 신호 유형별 템플릿 매핑 규칙

탐지된 위험 신호 유형(예: 선입금 유도, 연락 회피, 시세 과도 저가 등)에 따라 우선 노출할 템플릿을 매핑한다. 1개 신호당 우선 템플릿 1~3개를 지정한다.

MVP 신호 유형(예시 10개) → 우선 템플릿(각 1~3개)
1) 선입금/보증금 먼저 요구
- “선입금(보증금) 없이 거래 가능할까요? 안전결제/대면 거래로 진행하고 싶어요.”
- “계좌 명의(실명) 확인을 위해 예금주명과 신분 확인 가능한 자료를 받을 수 있을까요?”
- “입금 요청 사유와 환불 조건을 문자로 남겨주세요.”

2) 안전결제 거부/직거래 회피(택배만, 직거래 불가)
- “직거래가 어렵다면 안전결제(에스크로)로 진행할 수 있을까요?”
- “거래 전 제품 상태 확인을 위해 영상통화/사진 추가 제공이 가능할까요?”
- “택배 거래 시 발송 전 운송장/포장 영상 공유가 가능할까요?”

3) 연락 회피/통화 거부
- “통화/영상통화로 간단히 확인 가능할까요? 어려우면 본인 확인 자료를 부탁드려요.”
- “거래 조건(시간/장소/금액)을 문자로 정리해서 남겨주세요.”

4) 시세 대비 과도한 저가(급처/파격 할인)
- “가격이 시세보다 낮은 이유가 무엇인지, 하자/소유 경위 포함해 설명해주실 수 있을까요?”
- “제품(또는 권리관계) 증빙 자료(구매 영수증/등기 등)를 받을 수 있을까요?”

5) 외부 메신저/링크로 유도
- “앱/플랫폼 내에서 대화와 결제를 진행하고 싶어요. 여기서 계속 이야기할 수 있을까요?”
- “외부 링크는 열기 어렵습니다. 필요한 정보는 메시지로 텍스트로 보내주세요.”

6) 제3자 계좌/대리인 거래 요구
- “입금 계좌가 본인 명의가 맞는지 확인할 수 있을까요? 명의 불일치면 거래가 어렵습니다.”
- “대리인이 나온다면 위임장/신분 확인 자료를 받을 수 있을까요?”

7) 신분/소유 증빙 거부
- “신분 확인(이름/연락처)과 소유/권한 증빙(영수증/등기/임대인 동의 등)을 부탁드려요.”
- “증빙이 어렵다면 안전한 방식(공인중개사/안전결제/대면 확인)으로만 진행하겠습니다.”

8) 장소·시간을 계속 변경(약속 불안정)
- “약속 장소/시간을 확정해서 문자로 남겨주세요. 변경이 잦으면 거래를 중단하겠습니다.”
- “사람 많은 공개 장소에서만 거래 가능해요. 가능할까요?”

9) 급하게 결정을 압박(오늘만/지금 당장)
- “확인할 시간이 필요합니다. 오늘 확정이 어려우면 거래를 진행하지 않겠습니다.”
- “계약/거래 조건을 정리해 보내주시면 검토 후 답드릴게요.”

10) 계약/거래 조건이 비정상적으로 단순(서류 회피)
- “주요 조건(금액/일정/환불/책임)을 문서(메시지/계약서)로 남겨주세요.”
- “부동산 거래라면 공인중개사 통해 진행하고, 등기/권리관계 확인 후 계약하겠습니다.”

운영 규칙
- 결과 화면에서는 ‘사기 확정’ 표현 금지, ‘추가 확인 필요’ 톤 유지
- 복사/공유 전후에 ‘민감 정보 마스킹’ 안내를 항상 함께 노출
- 템플릿은 상황에 따라 3~8개를 추천하되, 각 신호의 우선 1~3개를 상단 고정 노출
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 시작전


#### 4.1.3 템플릿 안전 가이드(불법/위험 행동 방지)

추천 템플릿 하단에 안전 가이드를 고정 노출해 사용자가 위험한 선택을 하지 않도록 돕는다.

고정 노출 안전 수칙(기본 5개)
1) 선입금 최소화: 선입금/보증금 요구 시 거래를 멈추고, 안전결제(에스크로) 또는 대면 거래를 우선한다.
2) 본인/명의 확인: 계좌 예금주명, 신분 확인 자료, 소유/권한 증빙(영수증/등기/위임장 등)을 확인한다. 명의 불일치 시 거래를 중단한다.
3) 기록 남기기: 거래 조건(금액/일정/환불/책임)을 메시지로 정리해 남기고, 통화만으로 합의하지 않는다.
4) 공개된 장소/안전한 방식: 직거래는 사람 많은 공개 장소에서 진행하고, 가능한 경우 지인 동행 또는 낮 시간대를 선택한다.
5) 개인정보 최소 공유: 전화번호/계좌번호/주소/신분증 등 민감 정보는 필요 최소한만 공유하고, 공유/저장/전달 전 반드시 마스킹한다.

금지/주의 문구(노출 규칙)
- 불법·위험 행동 유도 금지: ‘신분증 원본을 보내라’, ‘원격 제어 앱을 설치하라’, ‘보증금을 먼저 보내라’ 등 사용자를 위험에 빠뜨리는 문구는 템플릿에 포함하지 않는다.
- 외부 링크/앱 설치 유도 주의: 외부 링크 클릭, 앱 설치(원격제어/인증서 등) 요청은 높은 위험 신호로 간주하고, 플랫폼 내 대화 유지를 권장한다.
- 단정 표현 금지: “사기 확정” 등 표현 금지, “추가 확인이 필요해요” 톤을 유지한다.

표시 위치(권장)
- 템플릿 목록 하단에 ‘안전 가이드’ 블록으로 고정 노출
- ‘추천 문구 복사’ 실행 후 토스트로 “민감 정보는 마스킹 후 사용하세요” 1줄 추가 안내
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 시작전


### 4.2 [NICE TO HAVE] 템플릿 복사 기능
> **중요도**: 🟢 낮음 | **진행 상태**: ⚪ 시작전

추천된 질문/요청 템플릿을 버튼으로 복사할 수 있게 한다.

MVP 원칙
- 복사 성공/실패만 간단히 안내한다.
- 화면/컨테이너별 UI 규칙(토스트 위치, Safe Area 등)은 MVP 문서에서 제외하고, 만들면서 조정한다.


#### 4.2.1 개별/전체 복사 버튼 제공

각 템플릿 항목에 ‘복사’ 버튼을 제공하고, 상단(또는 하단 고정 영역)에 ‘추천 문구 한 번에 복사’ 버튼을 제공한다.

동작 규칙(MVP)
- 개별 복사: 해당 템플릿 1개 문구만 클립보드에 복사한다.
- 한 번에 복사: 현재 화면에 노출된 ‘추천 템플릿’ 3~8개를 아래 포맷으로 묶어서 복사한다.
  - 첫 줄: “거래 전 추가 확인 문구(복사용)”
  - 각 항목은 줄바꿈으로 구분하고 번호를 붙인다.
  - 마지막 줄에 고정 안내를 포함한다: “※ 민감 정보는 마스킹 후 사용하세요.”
- 선택 기능이 없다면(기본): ‘추천’으로 노출된 항목만 대상(전체 템플릿 10개 전체 복사 금지).

예외/실패 처리
- 클립보드 권한 문제로 복사가 실패하면, 모달/영역에 전체 문구를 노출하고 사용자가 수동으로 드래그해 복사할 수 있게 한다(“수동 복사로 진행해주세요” 안내 포함).

컨테이너/UI 안전 규칙(MVP)
- 템플릿이 모달/드로어/모바일 바텀시트에서 열렸다면, ‘추천 문구 한 번에 복사’ 버튼(상단/하단 고정)이 시스템 UI(주소창/홈 인디케이터) 또는 컨테이너 버튼 영역에 가려지지 않게 여백을 확보한다.

버튼 문구(권장)
- 개별: “복사”
- 묶음: “추천 문구 한 번에 복사”
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 시작전


#### 4.2.2 복사 완료 안내(토스트/문구)

복사 실행 결과를 짧은 토스트(또는 화면 문구)로 안내한다.

노출 규칙(MVP)
- 성공 시: “복사 완료”
- 성공 시(추가 안전 안내 동반): 위 토스트 아래줄 또는 이어서 1줄로 “민감 정보는 마스킹 후 사용하세요”를 함께 노출한다.
- 실패 시(권한/미지원): “복사 실패. 길게 눌러 복사” 안내와 함께 복사용 텍스트 박스를 노출한다.

세부 규칙
- 토스트는 2~3초 후 자동으로 사라진다.
- 연속 복사 시 마지막 결과만 보이게 한다(토스트 중첩 방지).
- 모바일에서는 ‘길게 눌러 복사’ 문구를 기본으로 사용한다.

컨테이너/레이어 규칙(MVP)
- 템플릿이 모달/드로어/모바일 바텀시트에서 열렸다면, 토스트/안내 문구는 해당 컨테이너 내부(가려지지 않는 영역)에 노출한다.
- 토스트가 컨테이너 밖(뒤 화면)에 뜨는 방식은 금지한다(사용자가 즉시 확인 불가).
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 시작전

## 5. [FUTURE] 리포트 저장/공유
> **중요도**: 🟢 낮음 | **진행 상태**: ⚪ 시작전

리포트 저장/공유는 QA/운영 포인트가 많아 1인 MVP에서는 제외하고, 향후 범위로 둔다.

**수용 기준:**
```
1. ○ MVP 범위에서는 저장/공유 기능을 제공하지 않는다.
```


### 5.1 [REMOVE] 리포트 로컬 저장(로그인 없이)
> **중요도**: 🟢 낮음 | **진행 상태**: ⚪ 시작전

로그인 없이도 리포트를 기기(브라우저) 기준으로 저장하고, 저장 목록에서 다시 열 수 있게 한다.

근거: IndexedDB/LocalStorage 설계·예외·데이터 수명 등 운영성 이슈가 생겨 캡스톤 MVP 범위를 넘는다(Phase2/Future Scope).


#### 5.1.1 IndexedDB 또는 LocalStorage 기반 저장

로그인 없이 브라우저의 IndexedDB 또는 LocalStorage를 사용해 리포트를 로컬 기기에 저장한다. 저장 용량 제한(예: 최근 10개)을 설정한다.
> **중요도**: 🟢 낮음 | **진행 상태**: ⚪ 시작전


#### 5.1.2 저장 버튼 제공

결과 화면에 '저장하기' 버튼을 제공해 사용자가 언제든지 리포트를 저장할 수 있게 한다.
> **중요도**: 🟢 낮음 | **진행 상태**: ⚪ 시작전


#### 5.1.3 저장 완료 안내(토스트)

'저장하기' 클릭 후 '저장 완료' 토스트를 2~3초 노출해 사용자에게 성공을 알린다.
> **중요도**: 🟢 낮음 | **진행 상태**: ⚪ 시작전


### 5.2 [REMOVE] 저장 목록(생성일/위험도 요약 표시)
> **중요도**: 🟢 낮음 | **진행 상태**: ⚪ 시작전

저장된 리포트 목록에 생성일과 위험도 요약 정보를 함께 보여준다.

근거: 목록/상세/상태 동기화가 필요해 화면과 QA 범위가 급격히 커진다(Phase2/Future Scope).


#### 5.2.1 저장 목록 화면 진입 버튼

메인 화면 또는 네비게이션에 '저장한 리포트' 링크/버튼을 제공해 저장 목록 화면으로 진입할 수 있게 한다.
> **중요도**: 🟢 낮음 | **진행 상태**: ⚪ 시작전


#### 5.2.2 저장 리포트 목록 표시(생성일/위험도)

저장된 리포트를 리스트로 표시하되, 각 항목에 생성일(예: '2024.12.15 14:32')과 위험도 요약(예: '높음 (78점)')을 함께 표시한다.
> **중요도**: 🟢 낮음 | **진행 상태**: ⚪ 시작전


#### 5.2.3 저장 리포트 클릭해서 다시 열기

목록에서 리포트 항목을 클릭하면 해당 결과 화면을 다시 열 수 있게 한다(저장 시점의 상태를 그대로 노출).
> **중요도**: 🟢 낮음 | **진행 상태**: ⚪ 시작전


### 5.3 [REMOVE] 저장 리포트 삭제
> **중요도**: 🟢 낮음 | **진행 상태**: ⚪ 시작전

사용자가 저장된 리포트를 삭제할 수 있게 한다.

근거: 삭제 확인/복구 불가 안내/예외 처리 등 디테일 작업이 많아 MVP 구현 가능성에 불리하다(Phase2/Future Scope).


#### 5.3.1 각 저장 리포트 옆 삭제 버튼 제공

저장 목록의 각 항목 옆(또는 우측 끝)에 삭제(X/휴지통 아이콘) 버튼을 제공한다.
> **중요도**: 🟢 낮음 | **진행 상태**: ⚪ 시작전


#### 5.3.2 삭제 확인 다이얼로그

삭제 버튼을 클릭하면 '정말 삭제하시겠어요?' 확인 다이얼로그를 표시하고, '확인' 클릭 후 해당 리포트를 삭제한다.
> **중요도**: 🟢 낮음 | **진행 상태**: ⚪ 시작전
