## 1. [MUST] 텍스트 입력 및 AI 분석 요청
> **중요도**: 🔴 높음 | **진행 상태**: ✅ 완료

사용자가 중고거래/부동산 거래 관련 텍스트를 붙여넣고 분석을 요청하면, LLM이 위험 신호를 자동으로 추출한다.

핵심 원칙
- 텍스트 입력만으로 분석이 시작된다. 위험 신호를 미리 알 필요가 없다.
- 파일 업로드/링크 크롤링은 MVP 제외.

**수용 기준:**
```
1. ✅ 사용자가 텍스트를 입력하고 '다음'을 누르면 AI 분석 요청이 생성된다.
2. ✅ 최소 입력 길이(50자) 미만이면 요청이 불가하고 안내 메시지가 표시된다.
3. ✅ AI 분석 중 버튼이 비활성화되고 로딩 상태가 표시된다.
4. ✅ AI 호출 실패 시 빈 결과로 폴백, 사용자는 수동으로 신호를 선택할 수 있다.
```


### 1.1 [MUST] 텍스트 입력 화면
> **진행 상태**: ✅ 완료

사용자가 채팅 내용, 매물 설명, 계약 안내 문자 등을 붙여넣거나 직접 입력하는 화면.


#### 1.1.1 입력 예시/가이드 문구 노출
> **진행 상태**: ✅ 완료

입력 영역에 예시 placeholder와 입력 안내 문구("채팅 내용, 매물 설명, 계약 안내 문자 등을 그대로 붙여넣으면 됩니다.")를 노출한다.


#### 1.1.2 민감 정보 입력 경고(자동 감지)
> **중요도**: 🔴 높음 | **진행 상태**: ✅ 완료

전화번호/계좌번호/주민번호/이메일 형태가 감지되면 경고 메시지를 표시한다.


#### 1.1.3 텍스트 빠른 동작(붙여넣기/전체 지우기)
> **진행 상태**: ✅ 완료

붙여넣기 버튼과 '전체 지우기' 버튼 제공.


### 1.2 [MUST] AI 분석 요청 실행 및 로딩 상태
> **진행 상태**: ✅ 완료

'다음' 버튼 클릭 시 `/api/suggest`를 호출해 LLM 위험 신호 추출을 시작한다. 처리 중 버튼 비활성화 + "AI 분석 중..." 표시.


#### 1.2.1 /api/suggest 호출 및 상태 관리
> **진행 상태**: ✅ 완료

useSuggest 훅이 loading/error 상태를 관리. 성공 시 신호 ID 목록을 ChecklistForm에 전달.


#### 1.2.2 중복 요청 방지
> **진행 상태**: ✅ 완료

로딩 중 버튼 비활성화.


### 1.3 [MUST] 입력 검증(최소 50자)
> **진행 상태**: ✅ 완료

50자 미만 시 요청 차단 + "최소 50자 이상 입력해주세요 (N자 남음)" 안내.


### 1.4 [MUST] 요청 실패 처리
> **진행 상태**: ✅ 완료

AI 호출 실패 시 빈 배열로 폴백 → 사용자가 수동으로 신호를 선택할 수 있는 상태로 ChecklistForm 진입.

오류 문구:
- 네트워크 오류: "인터넷 연결을 확인해주세요."
- 기타 오류: "AI 추천에 실패했습니다." (수동 선택 가능)

## 2. [MUST] AI 추출 결과 검토/수정
> **중요도**: 🔴 높음 | **진행 상태**: ✅ 완료

AI가 추출한 위험 신호를 사용자가 검토하고, 잘못된 항목을 제거하거나 누락된 항목을 추가할 수 있다.

이 단계는 선택(SHOULD)이 아닌 필수(MUST)다 — AI 오류를 사용자가 교정하는 안전장치이기 때문.

**수용 기준:**
```
1. ✅ AI가 추출한 신호 항목이 미리 선택된 상태로 표시된다.
2. ✅ AI 추천 항목에 'AI' 배지가 표시된다.
3. ✅ AI가 몇 개 항목을 추천했는지 안내 문구가 표시된다.
4. ✅ 사용자가 항목을 추가하거나 제거할 수 있다.
5. ✅ AI 추출 없이도(폴백 시) 수동으로 신호를 선택해 분석 가능하다.
```


### 2.1 [MUST] AI 추천 항목 표시 및 수정
> **진행 상태**: ✅ 완료

- AI가 추천한 항목: 미리 체크된 상태 + 'AI' 배지 + 보라색 하이라이트 border
- AI 추천 안내 문구: "입력하신 내용을 분석해 N개 항목을 미리 선택했어요. 검토 후 수정하세요."
- 모든 항목 추가/제거 가능


### 2.2 [MUST] 수동 선택 가능
> **진행 상태**: ✅ 완료

AI 추출이 없거나 실패해도 체크박스로 직접 신호를 선택해 분석 가능.

## 3. [MUST] 위험도 리포트 생성(요약 + 점수)
> **중요도**: 🔴 높음 | **진행 상태**: ✅ 완료

최종 선택된 신호를 규칙 기반 점수 엔진에 전달해 위험도(점수/등급)와 핵심 위험 신호 목록을 리포트로 제공한다. 결과는 '판정'이 아닌 '추가 확인을 돕는 참고'로 안내한다.

**수용 기준:**
```
1. ✅ 리포트에 위험도 점수/등급이 표시된다.
2. ✅ 감지된 위험 신호 목록이 점수 내림차순으로 표시된다.
3. ✅ 결과 화면에 참고용/면책 문구가 표시된다.
4. ✅ 입력 텍스트 전문을 그대로 재노출하지 않는다.
```


### 3.1 [MUST] 위험도 표시(점수/등급)
> **진행 상태**: ✅ 완료

점수(0~100) + 등급(LOW/MEDIUM/HIGH) + 게이지 시각화.


### 3.2 [MUST] 감지된 위험 신호 표시
> **진행 상태**: ✅ 완료

AI가 추출하고 사용자가 최종 확정한 위험 신호를 카드/리스트로 표시. 각 신호에 심각도 배지 + 위험 이유 설명(1줄) 포함.

표시 규칙:
- 정렬: 점수 높은 순
- 단정 표현 금지("사기 확정" 등)
- "추가 확인이 필요해요" 안내 톤 유지

향후 추가 예정:
- 각 신호별 원문 근거 인용 (AI가 근거 문장을 함께 반환하도록 확장)


### 3.3 [MUST] 면책/주의 문구 노출
> **진행 상태**: ✅ 완료

"이 결과는 참고용 점검 도구이며, 법적 판단이나 전문가 의견을 대체하지 않습니다." 고정 표시.


### 3.4 [MUST] 입력 텍스트 재노출 최소화
> **진행 상태**: ✅ 완료

결과 화면에 입력 텍스트 전문을 재노출하지 않는다. 위험 신호 라벨과 설명만 표시.


### 3.5 [DONE] AI 위험 신호 추출 (백엔드)
> **중요도**: 🔴 높음 | **진행 상태**: ✅ 완료

`/api/suggest` 엔드포인트가 Claude Haiku를 호출해 텍스트에서 위험 신호 ID를 추출한다.

구현 내용:
- `apps/api/app/services/ai.py`: Claude Haiku 호출, JSON 파싱, ID 검증
- `apps/api/app/routers/suggest.py`: POST /api/suggest 엔드포인트
- `apps/web/src/hooks/useSuggest.js`: 프론트엔드 훅

AI 역할 제한:
- ✅ 텍스트 → 위험 신호 ID 추출
- ❌ 점수 계산 (scoring.py가 담당)
- ❌ 등급 판정 (scoring.py가 담당)

향후 확장:
- 신호별 원문 근거 문장도 함께 반환 (현재는 ID만 반환)


### 3.6 [MUST] 위험도 산출 로직(규칙 기반)
> **진행 상태**: ✅ 완료

선택된 위험 신호 ID를 입력으로 받아 고정 점수를 합산, 위험도 점수/등급을 산출한다.

```
점수 합산 = Σ(선택된 신호 점수)
최종 점수 = min(합산 점수, 100)

0~30  → LOW
31~69 → MEDIUM
70~100 → HIGH
```

같은 입력 → 항상 같은 출력 (결정적 결과).

## 4. [NICE TO HAVE] 근거 인용 표시
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 시작전

각 위험 신호 카드에 "어떤 문장 때문에 탐지됐는지" 원문 인용을 표시한다.

현재 AI 서비스는 신호 ID만 반환한다. 이 기능은 AI 서비스가 신호 ID + 근거 문장을 함께 반환하도록 확장해야 구현 가능하다.

**수용 기준:**
```
1. ○ 각 위험 신호 카드에 원문 근거 문장이 1줄(최대 80자) 표시된다.
2. ○ 민감 정보(전화번호/계좌번호 등)는 자동 마스킹된다.
3. ○ 근거가 없으면 신호 설명 1줄로 대체한다.
4. ○ "원문 보기/전체 보기" 버튼은 제공하지 않는다.
```

## 5. [NICE TO HAVE] 추가 확인 가이드(템플릿)
> **중요도**: 🟢 낮음 | **진행 상태**: ⚪ 시작전

위험 신호별 거래 상대에게 확인할 질문/증빙 요청 템플릿 추천.

**수용 기준:**
```
1. ○ 결과 화면에 '추가 확인' 섹션이 존재한다.
2. ○ 위험 신호 유형에 따라 3~8개의 템플릿을 추천한다.
3. ○ 템플릿은 복사 가능하다.
```

공통 템플릿 예시 (10개):
1. "선입금(보증금) 없이 안전결제/대면 거래로 진행하고 싶어요."
2. "계좌 예금주명 확인을 위해 명의와 본인 확인 자료를 받을 수 있을까요?"
3. "환불 조건/거래 조건을 메시지로 정리해 남겨주세요."
4. "직거래가 어렵다면 안전결제(에스크로)로 진행할 수 있을까요?"
5. "제품/매물 상태 확인을 위해 사진 추가 또는 영상통화가 가능할까요?"
6. "택배 거래라면 발송 전 운송장과 포장 과정을 사진으로 공유해주세요."
7. "거래 장소/시간을 확정해 메시지로 남겨주세요."
8. "가격이 시세보다 낮은 이유를 설명해주실 수 있을까요?"
9. "외부 링크/앱 설치는 어렵습니다. 텍스트로 보내주세요."
10. "부동산 거래라면 공인중개사 통해 진행하고 등기/권리관계 확인 후 계약하겠습니다."
